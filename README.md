# 剧本转分镜提示词

将中文剧本、剧情或动作笔记整理为项目分析、人物场景道具图片提示词、集场规划、整场时长预算与分段，以及逐段视频提示词。

技能标识：`script-to-storyboard-prompts`。技能包版本：**1.0.0**，当前规则与项目状态版本：**1.9**；原始单文本v1.8继续作为历史基线保存。1.0.0是规则集与工具的稳定版，承诺范围与未验证项见[发布说明](docs/1.0.0-发布说明.md)。

## 安装

用打包脚本生成安装副本。它只复制运行文件（`SKILL.md`、`references/`、`scripts/storyboard_checks.py`、`scripts/prompt_lint.py`、`evals/scenarios.md`、`evals/fixtures/`），写入哈希清单 `MANIFEST.json`，目标目录不为空时拒绝写入：

```bash
python -I scripts/build_package.py --output ~/.agents/skills/script-to-storyboard-prompts
```

不要直接复制整个 `evals/`：其中的 `runs/` 是约10 MB的历史验收与试点记录，运行时不需要。手动复制时只复制上面列出的文件，并保留这一层目录名。维护者在完整仓库中复跑回归；`docs/`、`specs/`、`tests/` 和 README 是说明与维护资料，不是正常文字制作的必读前驱。校验工具只用Python 3.10+标准库；没有Python的客户端仍可按规则进行文字核对，并如实标记程序检查未执行。

ZCode 支持用户级 `~/.agents/skills/`。安装后在新会话中从“设置 → Skills”或输入框 `/` 菜单确认发现情况。已有同名目录时先比较，不直接覆盖；用户 `.zcode/skills/` 中的同名技能可能优先加载。其他客户端的目录、刷新和调用语法以该客户端说明为准。

调用示例：

> 使用“剧本转分镜提示词”（script-to-storyboard-prompts）处理这份剧本，先完成项目分析，并让我确认视频画幅、画面质感和单段时长上限。

后续在该项目中说“继续”，每轮只完成当前下一单元。已采用其他制作流程的项目不会自动切换。

## 制作流程

1. 项目分析及三项制作条件确认。
2. 人物资产：首次同轮交付身份母图与四视图提示词。
3. 场景母图与核心道具提示词。
4. 按集规划，登记事件链与增量资产。
5. 整场分析，明确事实、空间、台词及揭示顺序。
6. 整场预算与合法分段，记录首尾承接。
7. 逐段完整视频母稿；指定模型时核验能力和素材后派生提交适配稿。

保留原台词、因果、结果与揭示顺序；先算整场时长再拆段；剧情覆盖、历史返修和状态恢复共用一份项目状态。普通摄影与不改变剧情的细节由模型设计，不增加独立分镜表或关键帧审批。

默认逐步交付文字。提示词完成不代表图片、视频或声音已生成；实际媒体生产需要明确要求和实际可用工具。制作项目的剧本、状态、资产记录、预算和产物保存在各自项目目录，避免写入技能目录。

## 执行细节与可选策略

各项检查的PASS须分别附实际范围和可定位证据；状态及预算程序通过不能替代原文、输入、平台能力或媒体检查。

镜头执行核对操作与目光是否兼容、连续短镜是否有必要、关键证据何时真正可读；返修追踪语义到达与下游依赖。涉及剪取、叠化或技术尾料时分别核算成片与素材时钟。

预览确认、段界换画面和静止锚点默认关闭；省略重复静态外貌只在适配稿有明确启用依据及真实输入时采用，完整母稿继续保留事实。详见[可选策略](references/model-adaptation.md#optional-strategies)。

## 镜头连接与转场

0.4.0将[转场执行方法](references/transitions.md)纳入包内参考：动作、图形／构图／颜色、视线、遮挡、甩镜与声音连接按需读取。整场分析明确关系，预算阶段登记相位和首尾，正式段把接法写进完整母稿；已有真实素材时再检查实际剪辑出入点与邻近运动。桥接、剪取和重叠继续归原预算与项目记录。

在已采用本技能的项目中可直接说：

> 继续当前正式段。按剧情选择需要的连接，保持原台词、已确认风格和预算；有精确匹配需要时读取对应转场方法。

只读检查可限定范围：

> 只检查第2段与第3段的动作衔接，给问题和修正建议。没有实际视频的部分只给计划，不推进新段。

这不是新增制作阶段；不强制每镜转场，不采用来源附件的默认平台、画幅或固定重试次数。单独咨询只交付所需解释或方案，不启动七步状态机。真实生成和剪辑仍按明确请求及可用工具执行。

## 状态与预算校验

0.3.0支持链内锚点和部分覆盖；返修后重新计算连续有效进度，保留仍有效的后续段；适配请求可明确取消并恢复原目标。母稿时间码统一相对本段0秒。旧项目按[1.9迁移说明](references/state-and-revision.md#s7-8)核对实际记录，不直接替换版本号。

新文件项目优先保存 `run-state.json` 和结构化预算，聊天仅展示短回执与文件位置。程序只检查明确字段、覆盖区间、版本映射和时间算术；剧情、表演、并行合理性和真实交付仍需要语义核对。使用方法及边界见[机械校验说明](references/validation.md)。

在完整仓库根目录运行：

```bash
python -I scripts/check_package.py
python -I -m unittest discover -s tests -v
```

一次运行两类检查并保存可追溯结果（每次使用新的结果文件名）：

```bash
python -I scripts/run_checks.py --output evals/runs/local-check.json
```

结果包含受测文件SHA-256、测试原始输出和退出码；输入在运行中变化或未发现测试时不会报告通过。已有结果文件不会被覆写。

检查项目文件时使用绝对路径，例如：

```bash
python -I scripts/storyboard_checks.py check --state /absolute/project/run-state.json --budget /absolute/project/segment-budget.json
python -I scripts/storyboard_checks.py derive --state /absolute/project/run-state.json
```

`check`、`derive`、`summary`、`receipt`和`cancel`不覆写权威状态；`cancel`和`patch`生成候选，只有显式`commit`（或`patch --commit`）才写回。`init`建立新项目状态。旧自由文本状态不由程序自动解析或迁移。

检查交给模型的正文：

```bash
python -I scripts/prompt_lint.py master --prompt /absolute/project/prompts/FORMAL_1/master-v1.md --state /absolute/project/run-state.json --source /absolute/project/source/script.md --formal-id FORMAL_1
```

## 验证说明

当前保持**分范围验收**：包结构和确定性回归使用上述命令；模型文字行为、客户端发现与触发、真实媒体另行验证。0.1.0／0.2.0历史测试与失败完整保留，不能因本版修订追溯改成通过。当前版本运行结果及限制见[实施与验收记录](docs/技能包实施与验收记录.md)。

`evals/scenarios.md`提供82个人工行为用例（含10个转场用例、10个0.5.0用例和2个0.6.0用例）及规则覆盖索引；`evals/fixtures/state-budget/`提供可移植的确定性回归数据。程序通过不自动将人工用例记为通过。新会话发现与自动触发、完整端到端制作尚未验证。

0.4.1已完成部分手动加载的用户模拟与独立判读，见[0.4.1用户模拟审查报告](docs/0.4.1-用户模拟审查报告.md)。0.5.0又做了一轮代码审查、流程模拟与独立评判，四版受测包的修复与归档见[0.5.0代码审查与用户模拟报告](docs/0.5.0-用户模拟审查报告.md)。0.5.0做了第一次真实媒体试点（gpt-image-2-ext生图15个任务、wan3.0-video视频6段），结论与证据范围见[媒体试点报告](docs/0.5.0-媒体试点报告.md)；试点只有一个样例，不代表其他模型或题材同样成立。

0.6.0只修订文字规则，把“点名排除无效”“门窗开向写成相机坐标”两项结论补上外部研究依据，并把“末帧接续”按厂商官方文档保留为常规做法、只加核验条件，**没有做新的媒体测试**：依据来自文生图、开源视频生成研究与厂商文档，与试点所用模型不同代，只用于判断写法是否可执行，不当作预期效果的依据。本技能交付的是可执行文字，画面效果由目标模型决定。核对层级、未采用的结果和四项可选探针见[外部依据修订](docs/0.6.0-外部依据修订.md)。

1.0.0**不新增规则**，只冻结交付面：`state_version`、`workflow_schema`、75个顶层字段、八个状态命令、82个用例编号与R01–R16覆盖索引在1.x内不再变动。它承诺的是规则集与工具接口，不承诺模型是否照规则执行、客户端能否发现、媒体效果或端到端成片。82个人工用例中只有1例有人工执行记录、64例完全未执行，这个比例写在[发布说明](docs/1.0.0-发布说明.md)里，不因版本号升为1.0而改变。
