# 0.5.0 媒体试点报告

试点日期：2026-11-06，时区Asia/Shanghai。这是本技能的第一次真实媒体测试（M方法），只覆盖一个样例故事、一组模型和下述做法，不代表其他模型、题材或参数同样成立。

## 测试条件

- 平台：apimart.ai，用户提供的Key。生图`gpt-image-2-ext`（文档说明与`gpt-image-2`等价），2K。视频`wan3.0-video`，720P，16:9，有声音，固定种子20261106。
- 用户提供生图与视频模型，明确要求全部做测试，并限定视频最多三轮、选择780p。这个Key可用的视频模型都没有780p，按最接近的720P生成。用户没有回答模型和每轮条数的确认问题，按建议默认值执行：wan3.0-video，每轮最多两条视频。
- 样例：0.4.1用户模拟中的原创剧本《值班室的灯》（许宁推门两段共9秒，再望向走廊说“灯还亮着。”）。基线提示词逐字节复制自0.4.1归档，哈希相同。
- 检查方法：图片全图目视，关键区域放大2倍。视频每秒抽帧，切点附近每0.25秒抽帧，取末帧；用ffmpeg计算每0.1秒的音频能量并绘制频谱。执行环境无法播放视频或收听音频：声音只能判断有无、时段和是否有语音谐波，不能确认说出的字词。
- Key保存在仓库外的`~/.config/storyboard-pilot/apimart.env`；记录写入前去除Key，[汇总](../evals/runs/0.5.0-media-pilot/summary.json)核对受跟踪文件中没有Key。

## 变量控制的限制

第1轮到第2轮同时改了文字、生成方式（纯文字→首帧）和首帧，不能把改善单独归于文字。真正只改一个变量的对照只有V2-A与V3-A（同首帧、同种子，只改文字）；V2-B与V3-B比较的是“同一次生成内切全景”与“全景单独生成”，两者首帧不同。每种做法只有1～2个样本。

## 结论与规则修订

| 现象 | 证据 | 修订位置 |
|---|---|---|
| 纯文字生成每次切镜都重建房间和人物；资产首帧开场后保持一致 | V1-A/B与V2-A | [帧链与分镜生成](../references/model-adaptation.md#frame-chaining) |
| 单独生成的四视图丢失性别 | IMG-02与IMG-05 | [B模板](../references/asset-templates.md#asset-b)、`IDENTITY_SEX_MISSING`检查 |
| 写实措辞把动画项目拉向写实 | IMG-01/04与IMG-06 | [A模板](../references/asset-templates.md#asset-a)、`STYLE_DRIFT_RISK`检查 |
| 唯一的单变量对照中，补写“没有标牌”的点名排除后，标牌仍在相同时刻出现；点名排除是否有用尚无证据 | V2-A、V3-A | [3.9](../references/shot-writing.md#s3-9) |
| 应向外开的门在4次生图中都画成向室内开（2次纯文字、2次带关门参考图；V2-B全景视频中也是）；图像编辑只验证了把门关上 | IMG-03/07、KF-02/02b、V2-B；IMG-07b | [E模板](../references/asset-templates.md#asset-e) |
| 左右手按离门远近分配，写明对应关系也无效 | KF-01、KF-01b、KF-01c | [3.9](../references/shot-writing.md#s3-9)、[I模板](../references/asset-templates.md#asset-i) |
| 末帧接续继承错误 | V2-A末帧与V2-B | [帧链与分镜生成](../references/model-adaptation.md#frame-chaining) |
| 同一次生成内切全景时补出窗户和文件夹桌；单独生成时布局稳定（告示板在切镜前的镜内跳变后已出现） | V2-B与V3-B | 同上，[两套时钟](../references/timing.md#s6-7)的分镜例 |
| 写了无字幕仍烧入字幕；首帧生成的频谱只有底噪 | V3-B；V2-A、V3-A | [3.9](../references/shot-writing.md#s3-9)、帧链 |
| 检测到的语音能量区间起点比计划晚0～0.7秒，字词未核实 | V1-B、V2-B、V3-B | [6.7](../references/timing.md#s6-7)记为观察，不改预算规则 |

正文检查在两份基线母稿上各报告约20条警告（制作用语、过程否定、镜头内世界方向和提前出现的下一段台词）；第2、3轮的四份适配稿中，V2-A、V3-A没有警告，V2-B有1处“上一段”，V3-B没有可识别的镜头标题（NO_SHOTS_PARSED），因此逐镜的时间和方向检查没有运行。结果写在[汇总](../evals/runs/0.5.0-media-pilot/summary.json)的lint字段。检查通过只说明措辞合规，不代表画面合格。
