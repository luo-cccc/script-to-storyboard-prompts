# 剧本转分镜提示词：技能化方案

- 更新日期：2026-11-03
- 技能标识：`script-to-storyboard-prompts`
- 规则基线：单文本规范 v1.8
- 当前状态：方案已完成主审与三个子 agent 的静态验证；本文件已合并审查修正，技能包尚未制作、安装或进行真实调用测试。

本文是当前技能化方案的统一入口。后续修改直接更新对应章节，不累积多份相互冲突的方案。原单文本规范作为迁移基线保留，研究报告作为历史比较资料保留。

## 1. 用途与触发

将中文剧本、剧情或动作笔记整理为项目分析、人物场景道具图片提示词、集场规划、整场时长预算与分段、逐段视频提示词，并支持模型提交适配、连续性检查和历史返修恢复。

第一版采用一个总控 Skill，七步流程共享同一份项目状态。默认交付文字；真实图片、视频或声音生产仍需用户另行明确要求，并依赖实际可用工具。

`SKILL.md` 的元数据使用以下内容：

```yaml
---
name: script-to-storyboard-prompts
description: >
  用户要求从中文剧本、剧情或动作笔记制作整套资产图片与视频分镜提示词，
  或继续、返修已采用本技能的项目时使用。
  依次完成项目分析、制作条件确认、人物场景道具图片提示词、
  集场规划、整场时长预算与分段、逐段视频提示词，
  支持模型提交适配、连续性检查和历史返修恢复。
  已明确采用其他制作流程的项目不自动切换到本技能。
---
```

目录名与 `name` 一致，文档标题和调用示例统一使用“剧本转分镜提示词”。元数据只使用已知支持的字段，不为中文名称另造配置字段。

单独询问摄影术语、咨询或维护技能时，只处理该请求，不启动制作状态。用户只说“继续”时，须有明确的当前项目及所采用流程；不能仅凭该词切换技能。

## 3. 共同入口与读取路由

### 3.1 先识别请求和项目

1. 区分正常推进、补适配、历史返修、普通重发、逐字复送、状态恢复、媒体检查，以及只读咨询。请求类型决定本轮职责。
2. 文件模式下，根据用户指定位置或已明确的当前项目定位项目根目录，核对 `project_id`、`state_ref` 与 `source_script_ref` 的归属。不能把技能安装目录或桌面规范文件的位置当成剧本项目目录。
3. 现有项目有多个候选或记录归属冲突时，只请求能解除歧义的最少信息，不猜测“最新项目”。新项目没有历史状态是正常情况；可在已明确的项目位置初始化，无法可靠保存文件时使用源规范已有的会话状态方式。
4. 正常推进前读取当前有效状态、适用状态转换规则和前驱交付证据，核对唯一 `next_required`、返修锁、当前依赖范围的阻断、覆盖连续前缀和原文游标，再锁定本轮目标。
5. 当前状态完整且证据一致时可正常继续。需要重建缺失或冲突状态时，按恢复分支先完成恢复，本轮不夹带新正式段。只读咨询和逐字复送不更新生产状态。

每轮按实际任务读取相关章节，不要求把全部参考资料反复读一遍；已在当前上下文且未变化的内容可以复用。缺少当前任务必要的文件或证据时说明具体缺项，不凭记忆声称已执行完整规范。

### 3.2 按任务补充读取

下表以共同入口为基础。文件名均指第 2 节的技能包内容；项目材料另从已定位的项目中读取。

| 当前任务 | 补充读取的规则 | 必需的项目材料与交付重点 |
|---|---|---|
| 第一步：项目分析与三项确认 | `shot-writing.md` 的风格写法；`camera-reference.md` 中相关光线、色彩、成像和构图内容；有参考素材时读素材职责总则 | 通读本次原剧本；完整分析后提出 2～3 个风格正文及三项制作选择，记录已确认与待确认项 |
| 第二步：人物资产 | `asset-templates.md` 总则及对应完整模板；`shot-writing.md` 的风格写法 | 已确认设定、人物档案、身高依据、适用造型／状态和复用证据；首次人物同轮交付母图与基准四视图 |
| 第三步：场景与道具 | `asset-templates.md` 对应模板；`shot-writing.md` 的风格与光照写法 | 场景空间、真实光源、道具结构与状态；默认逐项交付，先场景后道具 |
| 第四步：集规划 `EPxx_PLAN` | 入口的集规划规则、状态文件中的增量资产与返回规则；确有缺项时加载对应资产模板 | 当前集原文、稳定事件链、资产队列及造型／状态版本；发现缺项保存 `return_to`，补齐后返回原目标 |
| 第五步：场分析 `SCxx_ANALYSIS` | `shot-writing.md` 的观看任务、空间与连续性规则 | 当前场完整原文、人物关系、空间事实、原台词、有效前场末态及观看信息；完成后才进入预算 |
| 第六步：整场预算与分段 | `timing.md`；涉及具体平台限制时读 `model-adaptation.md` 相应条款 | 有效场分析、原文链、话轮卡、已确认上限、顺序／并行依据和首尾承接 |
| 第七步：正式视频段 `FORMAL_n` | `shot-writing.md`、`video-template.md`、`timing.md` 及相关摄影条目 | 本段原文、有效资产、场分析、预算分段、实际起态和前驱证据；完整母稿交付后按正文复算 |
| 指定模型提交适配 | `model-adaptation.md`、素材职责总则、适用预算与状态规则 | 有效母稿、对应原剧本版本与 `speech_id` 话轮卡、预算、实际素材及职责、目标模型能力依据；不能只比母稿或上游摘要 |
| 历史返修 | 按产物类型复用原任务读取路由，再加载返修规则 | 历史版本、修改要求、覆盖、预算、物理末态与观看信息依赖；完整重交付，复算实际受影响部分 |
| 普通重发／逐字复送 | 状态文件中的对应分支 | 定位请求的母稿或适配稿及原文；普通重发按原产物类型处理，逐字复送保持生产状态不变 |
| 状态恢复 | 状态文件中的恢复及迁移规则 | 最新完整状态、有效覆盖和正文、当前场预算分段、前驱证据、实际末态及未完成返修；恢复本身不消费剧情 |
| 已有媒体检查 | 状态文件中的媒体观察规则，以及被检查内容对应的规则 | 实际媒体、原文、母稿／适配稿、真实输入及任务证据；记录可检查范围、时码、偏差与归责依据 |

返修读取“原任务资料＋返修规则”，不只读返修章节。未受影响材料继续复用；素材缺失和能力未知按当前目标的实际依赖处理，不统一阻断所有文字交付。

## 4. 迁移时保留的执行约束

- **确认与交付节奏**：保留画幅、质感、单段时长上限三项明确确认，以及 `REVIEW / STRICT / ONE_AT_A_TIME`。每轮只完成锁定目标；“继续”不等于批量授权，也不代替未确认的制作决定。
- **资产完整性**：首次人物必须同轮交付完整母图与四视图，已有身份仅新增造型时按有效复用规则处理。场景与道具逐项交付，不因技能拆文件增加九宫格、布局图或独立关键帧审批。
- **原文与母稿**：保留原台词、事实、因果、结果和揭示顺序；母稿完整保留适用栏目，专业术语落实为具体执行。模型适配只转换表达和有据的输入承载，不替代完整母稿。
- **预算**：先计算整场事件、对白和动作，再按合法边界拆段；正式正文重新核算。顺序、并行及起点偏移分别处理；同一句跨镜对白只计一次，同句同语言适用表演的实测区间已含停顿时不重复加时。
- **覆盖与恢复**：新正式段完成相应交付和检查后才提交一次覆盖，按连续有效前缀推进。后补适配、重发、媒体生成或观察不重复消费剧情；待补事项保存原续作目标，当前可设 `WAIT_USER`，完成后恢复并停止。
- **返修影响**：局部修改保留正确内容和未受影响覆盖；物理末态、原文范围、段界或观看信息改变时，按实际依赖标记后续失效。逐字复送不编译、不复算、不更新生产状态；普通重发沿用源规范的重发记录规则。
- **证据边界**：文字检查、输入准备、模型能力和实际媒体结论分开。实际图片可读不等于已上传，文字 `DONE / COMPLETE` 不等于媒体通过；没有执行的测试不记录为实测。

这些约束是迁移验收重点。详细定义继续放在对应参考文件，避免在多个文件复制完整规则后各自修改。

## 5. 项目数据与版本管理

技能目录保存规则和模板；每个剧本项目保存自己的材料与状态。已有项目沿用实际文件位置，不为了统一目录强制搬动历史文件。新项目可以采用以下布局：

```text
剧本项目/
├── source/             # 原剧本及版本，或可核验的原文引用
├── run-state.txt       # 当前权威状态，包含覆盖和版本索引
├── assets/             # 资产提示词、素材记录及实际素材引用
├── scenes/             # 集场分析、预算和分段记录
└── prompts/            # 正式母稿、模型适配稿及历史版本
```

每个项目只维护一份当前权威状态；历史快照可以归档，但不得与当前状态混用。`state-and-revision.md` 保存规则，项目 `run-state.txt` 保存实例，二者职责不同。

继续沿用 v1.8 的 **75 个顶层状态字段及既有字段职责**：

| 信息 | 保存位置 |
|---|---|
| 模型能力、选择与依据 | `project_decisions` |
| 素材来源、职责和可用状态 | 所属资产记录或 `visual_reference`，其他位置引用 |
| 母稿与适配稿的版本映射 | `prompt_versions` |
| 对白实测与预算依据 | 语速卡及 `budget_ref` 指向的记录 |
| 交付、检查、媒体观察与真实任务 | 所属 `step_ledger` |
| 返修前目标与待恢复事项 | `edit_context`、`return_to` |
| 状态恢复证据 | `recovery_evidence` |

首版技能包沿用 `state_version=1.8` 和 `workflow_schema=SINGLE_TEXT_CONFIRMED_ASSET_STAGES_V3`。仅拆分规范文件不改变项目状态协议，也不因 schema 名含 `SINGLE_TEXT` 而改名。技能包自身的发布版本与项目状态版本分别管理。

母稿、预算、覆盖和适配稿通过已有版本关系关联；更新时保留历史和有效前缀，检查写入结果再报告成功。保存失败按原规范保留上一有效状态，并采用会话交付必要状态，不假报持久化成功。

## 6. 文件拆分与引用改写

拆分以内容职责为单位，保留完整模板与必要说明，避免只截取标题和字段名。需要处理以下引用：

| 原单文本写法 | 技能包中的处理 |
|---|---|
| “本文件”“这一个文本”“整份复制” | 按语义改为“本技能包”或具体文件；说明入口与所需参考文件一起使用 |
| “第三部分”“按 3.8” | 指向 `references/shot-writing.md` 的对应章节 |
| “第四部分” | 指向 `references/asset-templates.md`，需要时定位具体模板 |
| “第五部分”“5.1／5.2” | 分别指向完整母稿模板或模型适配规则，避免混为同一产物 |
| “第六／七／八部分”“文末资料” | 指向时长、状态或摄影参考文件的具体章节 |
| “保留用户《模板.docx》结构” | 可作为来源说明；包内已包含完整模板，不把原 Word 文件设为运行依赖 |
| “迁移携带本技能文本” | 携带技能入口及适用参考文件，并继续携带项目原文、状态、预算、有效产物和返修证据 |

执行指令中的 `references/...`、`evals/...` 地址以技能根目录解析，项目材料以项目根目录或已有可定位引用解析。Markdown 链接按所在文档位置写成能正确打开的相对链接；两种路径都须检查，不能把工作目录当成技能根目录。

正式落盘时为被引用章节设置稳定标题或锚点，并核对文件与锚点确实存在。对话中的源行号只作为审查证据，不作为安装后的长期引用方式。

### 7.2 待技能包落地后执行的用例

每条用例保存：前置状态、用户输入、应读取资料、预期交付、允许改变的状态、禁止改变的状态、实际输出及结论。以下是假定测试条件，不冒称真实媒体或供应商结果。

| 用例 | 关键断言 |
|---|---|
| 新项目分析与部分确认 | 先完整分析并给出风格正文；保存已确认项，仅追问缺项；三项未齐不进入资产 |
| 首次人物与增量造型 | 首次母图＋四视图同轮完整交付；有效身份增加造型时复用身份，不重复全项目 |
| 集规划、场分析及增量返回 | 两个独立目标均可路由；增量资产保留 `return_to`，补齐后返回；场分析后才预算 |
| 无模型、无图的正式段 | 前驱齐备时可交完整通用母稿；预算与正文一致，覆盖只提交一次 |
| 后补适配及必要输入缺失 | 对照原剧本、话轮卡和真实素材；缺首帧或必要能力时阻断对应目标，保留旧覆盖和恢复目标；新段直接提交受阻时不推进覆盖 |
| 同句实测计时 | 测试区间 0.5—7.7 秒已含句读与情绪停顿，另有 0.8 秒余韵：总计 8 秒；净发声未知记 `UNKNOWN`，已含项记 `INCLUDED` |
| 媒体问题与定点返修 | 假定 4.2 秒钥匙跳手，先记录证据与归责；仅审查不自行改稿，明确修稿后按锁与影响范围处理；不自动重投 |
| 历史修改、重发与逐字复送 | 局部修保留未受影响覆盖；改变末态或观看信息检查后续失效；母稿／适配稿按请求类型重发；逐字复送保持状态不变 |
| 正常继续与状态恢复 | 有完整状态时按唯一目标继续；需要恢复时先恢复并停止；项目归属不明不猜状态，也不把新项目缺旧状态当成错误 |
| 跨镜对白与空间连续性 | 同一句跨切镜只播放和计时一次；被裁掉的地标不等于消失；出入画核对路径、经过时间和持物；文件边界不自动等于切镜 |

触发测试另覆盖四类输入：明确调用技能名；从剧本制作整套资产与视频提示词；已采用本技能的项目中继续／返修；已采用其他制作流程或仅询问摄影术语。分别检查是否正确选择技能、是否错误切换流程或启动制作状态。

`evals/scenarios.md` 是普通测试资料，不会因目录名称自动运行。实际测试需加载技能、提供用例、检查输出和读取过程，并记录失败原因；静态关键词检查不能替代行为验证。

## 8. 实施与安装顺序

1. 在工作区制作技能包草稿，依据第 2 节映射提取内容，保留原单文本文件作为基线。
2. 补齐共同入口和全部任务路由，改写跨文件引用；删除重复说明，保留完整模板、预算与状态机制。
3. 核对迁移完整性、链接、元数据、名称和状态字段；执行第 7 节的适用场景测试，修正实际发现的问题。
4. 检查目标目录和同名技能后，将完整包放入用户级安装位置；若存在不同内容，先比较处理，不直接覆盖。
5. 在新会话确认技能发现、显式调用、自动触发和参考文件读取，记录通过范围与未测事项。
