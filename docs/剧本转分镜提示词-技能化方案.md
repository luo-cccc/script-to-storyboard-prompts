## 路径与项目数据

技能目录保存规则；制作项目保存自己的剧本、状态和产物。新项目可使用以下布局，已有项目沿用实际位置：

```text
剧本项目/
├── source/
├── run-state.json
├── assets/
├── scenes/
└── prompts/
```

每个项目只维护一份当前权威状态，历史快照另存。不能把技能目录、桌面规范位置或当前工作目录直接当作制作项目根；多个候选项目有歧义时请求最少定位信息。

执行指令中的 `references/...`、`evals/...` 以技能根解析；Markdown 链接按所在文件解析；项目材料按已定位项目根或已有可定位引用读取。跨文件章节使用稳定锚点，不能依赖迁移前的源行号。

## 状态与版本

沿用 75 个顶层状态字段及既有职责：

| 信息 | 权威归属 |
|---|---|
| 制作决定和模型能力依据 | `project_decisions` |
| 素材来源、职责和可用状态 | 所属资产记录或 `visual_reference` |
| 母稿与适配稿的版本关系 | `prompt_versions` |
| 语速、实测和预算 | 话轮卡及 `budget_ref` 指向的记录 |
| 交付、检查、真实任务和媒体观察 | 所属 `step_ledger` |
| 返修前目标及待返回事项 | `edit_context`、`return_to` |
| 恢复证据 | `recovery_evidence` |

技能包版本与项目状态版本分开管理。当前为 `state_version=1.9`、`workflow_schema=SINGLE_TEXT_CONFIRMED_ASSET_STAGES_V4`；75个顶层字段名称保持，链内游标、覆盖区间和取消生命周期属于语义升级。按[迁移规则](../references/state-and-revision.md#s7-8)核对实际证据后转换，不能只改版本号。已有run-state.txt可继续人工核对；转JSON后只保留一份当前权威状态。素材事实只保存一份，其他资料引用，不建立重复账本。

## 维护约束

- 保留三项明确确认和逐轮唯一目标；“继续”不替代缺失决定或永久批量授权。
- 首次人物同轮交付完整母图与四视图；先场分析、整场预算再合法分段，正式正文另行复算。
- 保留原台词、因果、结果与揭示顺序；母稿、适配稿、预算和状态分开交付。
- 新正式段只提交一次覆盖。适配、返修、重发和恢复沿用原机制，不自动重复消费剧情。
- 返修继承原任务所需资料；影响末态、边界或观看信息时，按实际依赖处理后续失效。
- 文字、输入、能力、媒体检查分别记录，未执行不称实测；不把收费媒体生产设为文字交付前驱。
- 不增加独立分镜表、关键帧审批、固定镜数或未经核验的平台限制。

模板来源提及原 Word 文件仅作来源说明，包内已有完整模板，不作为运行依赖。保留单文本[原始规范](../specs/script-to-storyboard-prompts-v1.8.txt)供迁移比对；历史[资源研究](./分镜资源对比研究-2026-11-03.md)继续保持 v1.7 比较基线。

后续修改先核对原文、模板、公式、状态字段和链接，再执行适用行为用例。发现、自动触发、文字行为和真实媒体分别验收。未安装或环境未准备记 `NOT_RUN`；已执行而失败的检查记 `FAIL`，不能以预期代替实际结果。

操作目光、连续短镜和阅读窗口归镜头规则；两套时钟归时长6.7；语义到达与后续依赖归返修7.6；四项可选策略归模型适配与交付层。入口仅提供读取路由，不重复维护整段说明。预览是用户选择的交付方式，不是新增默认阶段；完整母稿和原75字段保持。

## 0.3.0 执行层与验证

- 源内锚点、半开覆盖、连续前缀归并及取消恢复归状态7.4／7.5／7.6；适配生命周期归5.2；段时钟归时长6.6和母稿模板；单点透视定义在摄影条目内修正。
- [storyboard_checks.py](../scripts/storyboard_checks.py)处理标准JSON的结构与机械不变量，候选检查和状态提交分开。它不解析旧自由文本、不自动认定语义前驱、不验证生成平台或媒体。预算只验证明确提供的记录，引用存在不代表内容已经人工验收。
- [check_package.py](../scripts/check_package.py)核对文件、链接、锚点、字段顺序、当前版本、原v1.8校验值及用例结构。[tests/](../tests/)和[夹具](../evals/fixtures/state-budget/)是可重复执行的D类证据；人工H、客户端F、媒体M单独记录。
- [run_checks.py](../scripts/run_checks.py)一次运行包检查和单元回归，保存受测输入哈希、原始输出、退出码及测试数量；运行中输入改变或未发现测试时不报告通过。已有运行记录不覆写，重新运行使用新文件名。
- 保存遵循候选校验、版本文件先存、权威快照最后原子替换。当前阶段保留完整快照和既有历史记录；完整事件日志重放尚未实现，不声称已采用完整事件溯源架构。

资产按当前集／场按需准备仍属可选后续方案，默认七步顺序不变。评估时应使用同一剧本比较首次可用段等待轮数、返修量、状态篇幅和恢复成功率；不能仅因工具已加入就改写用户既有制作约定。

## 0.4.0 转场方法归属

[转场参考](../references/transitions.md)负责需要细化的连接方法，入口仅增加按需读取路由。普通切换继续由镜头规则处理；不增加第八步、独立TRANSITION生产单元或媒体前驱。包内内容可独立运行，不依赖原TXT或另一个技能的安装。

三类方向与不变量归镜头执行，实际出入点及桥接时长归预算，素材职责与首尾能力归适配。段间计划沿用transition_plan，段内核对沿用transition_review；真实静态、动态、声音、拼接证据归所属media_observations，不另建账本。

本次保持状态1.9、V4 schema及75个顶层字段。只增加参考规则、用例与包必备文件清单，不新增机器格式必填项，也不要求旧项目迁移。正文完整模板、剧情保护与原有等待规则继续适用。

## 0.4.1 检查证据的入口提示

用户模拟发现部分INPUT PASS只保存“已读”范围而无单项证据引用；7.9中的通用检查职责现同步明确到入口交付检查与7.3步骤记录模板，使没有实际媒体的资产阶段也能直接读取。既有G02-01补充对应断言，不增加用例编号或状态必填结构。程序仍只执行声明的机械检查，不把这一提示修订说成所有H行为已保证通过。

同轮模拟还出现条件计划正文写BLOCKED、通用短回执却带“已完成”的矛盾。入口交付检查与7.2明确区分本轮交付内容和用户目标完成状态，G05-02补充对应回执断言。此为执行记录的防误用提示，原阻断与覆盖逻辑保持。
