# 1.0.0 发布说明

发布日期：2026-11-07，时区Asia/Shanghai。技能包版本1.0.0；规则与项目状态版本仍为1.9，`workflow_schema=SINGLE_TEXT_CONFIRMED_ASSET_STAGES_V4`。

## 定位

1.0.0是**规则集与工具的稳定版**，不是"效果已验证版"。它冻结的是交付面：规则不再改动、工具接口不再变动、状态结构不再扩张，使在制项目和已写入的提示词规则可以长期依赖。

它不改变制作范围：仍只交付文字提示词，不生成图片、视频或声音。

## 承诺

1. 按[入口](../SKILL.md)与参考文件执行，得到完整、内部一致、与剧本事实相容的文字交付：项目分析、资产提示词、集场规划、场次分析、时长预算与分段、逐段视频母稿，以及指定模型时的提交适配稿。
2. 状态与预算的结构、区间、版本映射和提交边界由[校验工具](../references/validation.md)确定性检查，结果为可复现的通过或失败。
3. 规则与工具在1.x系列内保持兼容：不修改`state_version=1.9`的字段集与顺序，不修改八个状态命令的名称、必填参数和退出码语义，不修改82个人工用例的编号。
4. 每项结论都标注依据类型与核对层级；本项目未执行的检查一律记`NOT_RUN`，不写成通过。

## 不承诺

1. **模型是否按规则执行。** 措辞规则提高可执行性，不保证任何模型的实际输出。文字检查通过不等于画面合格。
2. **客户端自动发现与自动触发。** 技能包的可发现性、`/`菜单呈现、与其他制作流程的语义竞争均未测试（F未执行）。
3. **媒体效果。** 只有一次单样例真实媒体试点，结论见[0.5.0媒体试点报告](./0.5.0-媒体试点报告.md)。其他模型、其他题材、首尾帧模式、R2V模式、口型与1080P均未验证。
4. **端到端成片交付。** 没有做过从剧本到成片的完整项目。

| 状态 | 数量 |

**这个比例是1.0最需要被看见的数字**：规则与工具已验，模型行为基本未验。按[实施与验收记录](./技能包实施与验收记录.md)的分范围验收口径，两者不能互相代替。

## 冻结清单

在1.x系列内不变：

- `state_version=1.9`、`workflow_schema=SINGLE_TEXT_CONFIRMED_ASSET_STAGES_V4`、75个顶层字段的名称与顺序
- 八个状态命令：`init`／`check`／`derive`／`summary`／`patch`／`cancel`／`commit`／`receipt`
- 退出码：0成功、1检查失败、2输入或IO错误
- 82个人工用例编号（G01–G15、T01–T04）与R01–R16规则覆盖索引
- 技能标识 `script-to-storyboard-prompts` 与七步流程的阶段划分

允许在1.x内调整：措辞、示例、解释性文字、参考资料的补充说明；不改变上述结构。

## 从0.x升级

1. **在制项目可以直接续作。** 状态结构未变，`state_version`仍为1.9，不需要迁移。

2. **旧交付不会被自动改写。** 0.6.0改变了三项规则（正向写法成为必须、点名排除判为无效、门开向改用相机坐标描述），但已交付的母稿和适配稿保持原样。只有两种情况会改：用户明确要求返修，或新产出与该段实际事实冲突。按仓库规则，历史记录不追溯改写。

3. **重新安装以取得新规则。** 0.x的安装副本不会自动更新，见下节。

4. **旧版本的`runs/`记录保留。** 0.1.0至0.6.0的验收与失败记录原样保留，不因为1.0发布而改判通过。

## 安装

用打包脚本生成安装副本，只含运行文件并写入`MANIFEST.json`：

```bash
python -I scripts/build_package.py --output /absolute/path/to/script-to-storyboard-prompts
```

目标目录非空时脚本拒绝写入，已有同名副本需先移走。不要直接复制整个仓库：`evals/runs/`是约10 MB的历史记录，运行时不需要。

安装后需要在客户端确认发现情况。**这一步没有被本项目验证过**：仓库没有执行F类检查，`MANIFEST.json`只保证文件完整与哈希一致，不保证客户端会加载。

## 已知限制

以下问题在1.0.0仍然存在，均记录在对应报告里：

- 门窗开合方向在试点中4次生图全部画错，改写为相机坐标只能消除正文歧义，不保证渲染方向。
- 左右手在试点中三次写明均未纠正，可靠做法只有生成后翻转或局部重绘。
- 写了“无字幕”仍可能烧入字幕，尚无验证过的预防办法。
- 末帧接续的接缝完全一致，但末帧的错误会被整包继承。
- 纯文字生成每次切镜都重建房间与人物；用资产首帧开场可保持一致性。
- 0.4.1的R1历史缺口保留：11条继承的旧PASS没有单项证据，主模拟记录质量仍为PARTIAL。
- 0.1.0／0.2.0的历史失败（人物用光方向矛盾、完整状态交付可靠性）保留原样。

## 1.x版本策略

- 1.x内的修订只改措辞、示例与解释，不改冻结清单。
- 需要改动状态字段、命令接口或用例编号时，升2.0并给出迁移说明。
- 每版发布附一份`evals/runs/<版本>-acceptance.json`，记录受测文件哈希、测试数量与退出码；输入在运行中变化时不报告通过。
